# Boiler Monitor — Мониторинг котельной и ГВС

Легковесный веб-дашборд на Go для визуализации температур в системе отопления и горячего водоснабжения (ГВС) в реальном времени. 

Приложение опрашивает внешний HTTP-сервис (например, микроконтроллер ESP32 с датчиками DS18B20), кэширует данные и отображает интерактивную мнемосхему котельной с анимацией потоков теплоносителя, фильтрацией кратковременных сбоев и аварийным оповещением.

## Основные возможности

* **Интерактивная SVG-схема**: наглядное отображение газового котла, бойлера косвенного нагрева (БКН), радиаторов отопления, тёплого пола и направления потоков воды.
* **Цветовая индикация**: плашки датчиков автоматически меняют цвет в зависимости от температуры (холодная, тёплая, горячая).
* **Фильтрация сбоев датчиков (`-127.0 °C`)**: кратковременные ошибки чтения шины 1-Wire игнорируются в течение 60 секунд — на экране удерживается последнее корректное значение.
* **Аварийная сигнализация**: если датчик не отвечает дольше 1 минуты, плашка переходит в статус `⚠ ERR`, поверх экрана появляется предупреждающий знак, меняется favicon вкладки и воспроизводится звуковой сигнал (через Web Audio API).
* **Автономность**: статические файлы (HTML/CSS/JS) встраиваются в единый бинарный файл при сборке, внешние зависимости не требуются.
* **Резервное хранение**: последние валидные показания сохраняются в `temp.json` и подхватываются при перезапуске сервера.

## Формат ожидаемого ответа от HTTP-сервиса (ESP32)

Сервер периодически выполняет `GET`-запрос по адресу, указанному в `conf.ini`. Внешний контроллер должен возвращать JSON-объект со статусом `200 OK` и заголовком `Content-Type: application/json`:

```json
{
  "boiler_coil_in": 62.5,
  "dhw_out": 54.0,
  "heating_return": 41.2,
  "heating_supply": 55.8,
  "floor_return": 32.4
}
```

### Описание полей

| Ключ JSON | Назначение датчика | Единица измерения |
| :--- | :--- | :--- |
| `boiler_coil_in` | Подача теплоносителя в змеевик БКН (бойлера) | °C (float) |
| `dhw_out` | Выход горячей воды (ГВС) из бойлера | °C (float) |
| `heating_supply` | Подача в контур радиаторного отопления | °C (float) |
| `heating_return` | Обратка котла / радиаторов отопления | °C (float) |
| `floor_return` | Обратка контура тёплого пола | °C (float) |

> **Примечание:** Значение `-127.0` воспринимается системой как стандартный код ошибки обрыва датчика DS18B20.

## Конфигурация (`conf.ini`)

При первом запуске программа автоматически создаст файл `conf.ini` со значениями по умолчанию, если он отсутствует рядом с исполняемым файлом:

```ini
[server]
port = 8080

[esp32]
url = http://192.168.1
poll_interval = 5s
```

* `port` — порт, на котором запустится веб-интерфейс.
* `url` — адрес HTTP-эндпоинта микроконтроллера. Если оставить пустым (`url = `), сервер будет работать в режиме чтения локального файла `temp.json`.
* `poll_interval` — интервал опроса датчиков (например: `2s`, `5s`, `1m`).

## Сборка и запуск

### Локальный запуск (для разработки)
```bash
go run .
```
После запуска интерфейс будет доступен по адресу `http://localhost:8080`.

### Сборка для Linux (x86_64)
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o boiler-monitor .
```

### Кросс-компиляция для ARMv7 (Raspberry Pi, Orange Pi, роутеры)
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -ldflags="-s -w" -o boiler-monitor .
```
*(Для более старых плат на архитектуре ARMv6, таких как Raspberry Pi 1 / Zero, укажите `GOARM=6`).*

### Запуск в качестве службы systemd (Linux)

1. Скопируйте скомпилированный файл `boiler-monitor` в `/opt/boiler-monitor/`.
2. Создайте юнит-файл `/etc/systemd/system/boiler-monitor.service`:

```ini
[Unit]
Description=Boiler Room Monitoring Dashboard
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/boiler-monitor
ExecStart=/opt/boiler-monitor/boiler-monitor
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

3. Запустите сервис и добавьте его в автозагрузку:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now boiler-monitor
```
